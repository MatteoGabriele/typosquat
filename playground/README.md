# Playground

A single page for trying the rules by hand: type a GitHub login and watch it get
scored against the protected set, with the rule that fired, the confidence band
and a character-by-character alignment against the login it resembles.

```bash
pnpm playground
```

That builds the rules, serves the page on `http://localhost:4173`, opens your
browser, and watches `src/` — edit a rule and the page reloads on its own. Set
`PORT` to use a different port. `pnpm playground:build` just produces the bundle
without serving.

| File | |
| --- | --- |
| [`index.html`](index.html) | Markup and styles. No dependencies beyond a Google Fonts link. |
| [`page.js`](page.js) | The UI — alignment diff, score meter, runners-up. |
| [`entry.ts`](entry.ts) | Re-exports `check`, `isBotLogin`, `severityOf` and `TRUSTED` from [`../src`](../src). |
| [`serve.mjs`](serve.mjs) | Dev server: build, serve, open, watch, live-reload. No dependencies. |
| `check.iife.js` | Generated by `pnpm playground`, git-ignored. Rebuild it after any change to `src/`. |

It runs the real rules, not a copy. The bundle is a plain global script rather
than ESM, so `index.html` also works opened straight from disk if you would
rather skip the server — `file://` blocks module imports, but not classic ones.

The "protected set" panel is editable: the textarea is the action's `protect:`
input, and the list below it is [`src/known-bots.ts`](../src/known-bots.ts). The
`allow:` input is deliberately absent — it short-circuits before any rule runs,
so there would be nothing to see.
